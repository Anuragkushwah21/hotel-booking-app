# Manual migration steps (historical)

> **Superseded.** The project now uses `prisma/migrations/` (see AUDIT.md →
> "Database deploy"). `0_init` contains everything 001–004 produced, including
> `generate_booking_ref()`. These files are kept only for reference — do not
> run them against a database that already has the migrations applied.

This project has no `prisma/migrations/` history: the schema is applied with
`prisma db push`, plus the SQL files in this folder for the steps `db push`
can't do on its own (database functions, data backfills).

Always take a backup first (Neon/Supabase: create a branch or snapshot).

## 001_dual_booking.sql

Repoints legacy `USER` role rows to `GUEST` before the role enum changes.

```bash
psql "$DATABASE_URL" -f prisma/manual/001_dual_booking.sql
```

## 002_booking_reference.sql

Adds `Booking.reference` — the short booking number (`HB-7K4M2Q`) a guest
quotes at the desk or types into `/booking-status`. The value is generated by
`generate_booking_ref()` in the database, so seeds and manual inserts get one
without any application code. Run it before `prisma db push`: the column's
default calls the function, so the function has to exist first.

```bash
psql "$DATABASE_URL" -f prisma/manual/002_booking_reference.sql
```

## 003_payment_flow.sql + 004_payment_backfill.sql

Online payment auto-confirmation, the payment ledger, pricing rules, refunds
and the notification log. 003 is purely additive (new enum values, new
nullable/defaulted columns, new tables), so it is safe on live data. 004 fills
the new money columns for bookings that already exist, writes one ledger row
per historical payment and creates the default settings row. Both are
idempotent.

```bash
# Option A — apply the exact SQL
psql "$DATABASE_URL" -f prisma/manual/003_payment_flow.sql
psql "$DATABASE_URL" -f prisma/manual/004_payment_backfill.sql

# Option B — let Prisma apply the schema, then backfill
pnpm prisma db push
psql "$DATABASE_URL" -f prisma/manual/004_payment_backfill.sql

pnpm prisma:generate
```

Run 003 and 004 as separate commands: PostgreSQL won't let a transaction use
an enum value added in the same transaction.
